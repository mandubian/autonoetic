Autonoetic · Visual Maps

Four ways to read the system

Autonoetic is a runtime where an AI agent — knowing its own past, capabilities, and rights, and bound by the same constitution as every other actor — becomes a trusted member of a community rather than a tool that has to be watched. These maps render that design at four altitudes. Each is a single self-contained page; open one and dig.

architecture-map.html

Governance architecture

Functional autonoesis and the community-of-equals framing; the bind-direction constitution (rules / rights / obligations / served); enforcement & contract health; the standing governance offices; the amendment lifecycle; and the whole rendered as one correction loop.

 technical-map.html

Technical infrastructure

The tool-call lifecycle, the four sandbox drivers, the three storage classes, the credential vault, the egress label plane (lattice · chokepoint · routing · labels at rest · declassification grants), the agent-birth pipeline, and the native tool surface.

 runtime-dynamics.html

Runtime dynamics

The temporal dimension: the session-lifecycle state machine and the persisted lifecycle-state vocabulary it maps onto, the approval & escalation swimlane (suspend-to-checkpoint, resume-with-real-result), the per-turn signed self-model, and the per-turn egress label flow.

 federation-data-model.html

Federation & data model

OFP node-to-node federation (topology, the HMAC + constitution-digest handshake, compatibility modes, wire protocol), the gateway.db entity-relationship model — the spine columns, the core ER diagram, the load-bearing tables incl. the egress label plane — and federation carry-forward: the three-digest model behind reusing a gate verdict across a rebuild.
