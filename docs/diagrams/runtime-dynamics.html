Autonoetic — Runtime Dynamics

The three things prose tables fight you on: how a session moves through its states, how it pauses for a human and resumes, and what verified self-model the gateway hands the agent on every single turn.

Third companion to the governance map (System Architecture) and the Technical Map. Those two are largely static structure; this one is the system in motion — the temporal dimension.

§ A — State Machine

The session lifecycle

A session is always in the turn loop or parked at a yield point. There are exactly twelve ways it can yield (the YieldReason enum), and every one writes a checkpoint. As enforced, they sort into seven resumable (the session suspends and continues) and five terminal (it closes). What the constitution's Ri-0.12 contributes is that the list is closed — any exit outside it is a gateway bug, not an accepted behaviour. Its clause text still enumerates an earlier 11-variant split; see the note below.

resumable · 7

Suspends, then continues

Four auto-resume on re-entry — Hibernation, WaitingForChild (Ri-0.14 wake-not-poll), Idle (a resident session parked only so peers can still reach it — nothing is being waited on), and ManualStop (the operator's cooperative pause). Three wait for an external decision — an approval, a user answer, or operator guidance (§ B); their checkpoint is HMAC-signed.

terminal · 5

The session closes

Budget exhaustion, the LoopGuard halt (MaxTurnsReached), the operator circuit breaker (EmergencyStop — never resumes), an unrecoverable Error, or an orphaned child (ParentTerminated).

footnote · distinct axis

Crash recovery ≠ continuation

A separate function, should_auto_resume_checkpoint_yield_reason, restarts Hibernation, Idle, BudgetExhausted, WaitingForChild, ManualStop and Error on gateway re-entry with no external input — so a terminal BudgetExhausted/Error close is recoverable once the condition clears. That is a different axis from the terminal/resumable split above.

pause ≠ stop

ManualStop is the cooperative pause, not a kill

Its only producer is root_session.pause (the room TUI's p). It yields at the pre-LLM checkpoint, so the in-flight tool batch finishes and only the next model call is prevented — then the session parks as Paused and continues in place on the operator's next message, no fork. That is the whole distinction from EmergencyStop, which hard-aborts and never resumes; Esc deliberately does not arm the circuit breaker.

This page's counts were always the enforced code; the amendment makes the law match. The version is signed + activated separately ("Signing runbook" in the version's RATIFY.md); until then the active constitution remains 2026.07.30 and this note stays accurate.

Two guarantees make this a closed system, not a maze. Ri-0.12: a session may terminate only through this declared list — any exit outside it is a gateway bug, not an accepted behaviour. And every yield point writes a checkpoint, so any past state is a runnable snapshot: a fork (session.fork) branches a fresh session from any checkpoint into its own lineage.

Two vocabularies — why a yield reason is not a lifecycle state

YieldReason answers why did this turn stop. It is a per-yield fact written into the checkpoint. What an observer — the room TUI, a workflow join, the orphan reaper — actually reads is a different, coarser vocabulary persisted on the session row: SessionLifecycleState. Several yield reasons collapse into one state, so the two lists are deliberately not the same length.

Why paused is not hibernated

Both park and both resume on the next message, so collapsing them looks harmless. It isn't: hibernated means the agent finished its turn, paused means the operator stopped it mid-task. The room needs the difference to know whether p pauses or resumes, and a paused session must block its workflow from completing where a hibernated one need not.

One vocabulary, mechanically

The states were string literals scattered across ad-hoc SQL and Rust until they were centralised in one enum. Classification now happens through exhaustive methods (is_terminal, is_resumable, permits_workflow_completion), so adding a state is a compile error at every site rather than a silent misread in some other file.

One asymmetry is deliberate: writers parse strictly (a writer must never invent a value), but readers classify via classify_stored, which honours the terminated: prefix — so a row written by a newer gateway is still correctly read as terminal. Strictness on the read path would re-introduce the exact failure the enum exists to prevent, one version boundary out.

§ B — Multi-Actor Flow

Approval & escalation — the human in the loop

When an agent proposes something privileged, the turn doesn't fail or fake a retry — it suspends to a signed checkpoint and resumes with the real result once a decider acts. Read the swimlane top-to-bottom; the number tells you the order, the column tells you who holds the baton.

Agent · reasoner
Gateway · enforcer
Decider · operator
1Proposes a privileged tool call (e.g. agent_revision_promote, remote sandbox_exec).
2Policy engine: approval required. Creates an ApprovalRequest row.gateway owes typed DecisionContext · Ri-0.15
3Checkpoints the session (YieldReason::ApprovalRequired) — HMAC-signed continuation. Turn suspends.runtime/continuations/<task_id>.json
4Sees it in the unified queue: operator.pending aggregates approvals, interactions, escalations, plan-frames.
5Decides — owes a motivation and is attributed on the chain.O-1 motivated · O-2 attributed
6apply_decision → scheduler wakes the session from its checkpoint.
7Injects approval_ref, resumes the loop, runs the tool for real, and finishes the batch.
8Receives the real tool result in history — no synthetic retry. Checkpoint is deleted.

The agent never gains privilege from the approval — it authorizes the gateway's execution path, not an escalation inside the agent runtime. And the suspension is tamper-evident: the continuation is HMAC-signed and its pending action is checked for equality against the stored approval, so a swapped-out action after approval (a TOCTOU attack) is rejected.

Two escalation kinds — don't confuse them
blocking · in-session

session_escalate → human

The agent is stuck and asks for guidance. This suspends the turn (YieldReason::HumanEscalation); the operator's guidance note is injected as a system message on resume. Targets reasoning_llm / specialist are advisory and non-blocking instead.

async · promotion

federation_escalate → operator

The planner bundles federation verdicts into an EscalationMessage for admin.escalation_resolve. It does not suspend the planner; the FullJury promotion gate mechanically refuses to promote without an approved escalation.

Egress — the per-turn label flow (data-envelopes)

1 · Taint accumulates

As the turn's context is assembled, each input's EgressLabel is intersected into the batch — a monotonic narrowing. A tool result read from a local_only source taints the batch local_only; it never widens back.

2 · Provider chosen to fit

The gateway selects a model whose class the batch label allows — rerouting to an eligible local preset, or refusing the turn if none qualifies, rather than sending restricted content to a remote model. Emitted as egress.provider_selected.

3 · Chokepoint withholds

The wrapping policy driver makes the last check: any message or tool result whose label excludes the target sink is replaced by an indication before the request leaves — egress.boundary_refused when it must withhold.

The one exit from monotonic narrowing — and it is the operator's, not the agent's

Steps 1–3 only ever narrow, which by itself would make a mislabelled input an unrecoverable dead end. The release valve is a declassification grant (P-15.3): the operator explicitly widens a label, content- or host-scoped, optionally expiring and revocable at any time. A refusal offers the grant that would unblock it, so the turn presents a decision rather than a wall — and expiry/revocation are re-checked when the grant is used, not merely when it was issued. Never inferred from content, never agent-set, never LLM judgment; recorded as egress.declassified.

Taint also crosses session boundaries, not just requests: it propagates into spawned children, rides agent_message between peers, and is fail-closed on inbound OFP messages — so widening has to be granted at the boundary it actually applies to rather than side-stepped by delegating the work to a child.
