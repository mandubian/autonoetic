Technical companion · runtime infrastructure

Autonoetic — The Technical Map

Beneath the constitution sits the machinery that makes it real: how a proposed tool call becomes a sandboxed effect, where everything is stored, what can never be quietly changed, and the full catalog of tools and default agents that operate on it.

Companion to the governance map (Autonoetic — System Architecture). Where that page answers why the rules are legitimate, this one answers how the runtime actually executes, stores, and recovers.

§ A — The Substrate

From proposed intent to sandboxed, audited effect

The agent proposes; the gateway validates, executes in isolation, records the result, and — if it failed — feeds a structured error back for repair. Every layer below is something the agent asks for but never touches directly.

The tool-call lifecycle
Reason

Agent — proposes a tool call

A typed intent (content_write, sandbox_exec, agent_spawn…) sent over JSON-RPC. The agent holds no execution authority; it holds permission to ask.

↓JSON-RPC intent
Gate

Tool dispatch & policy

Four checks in order: exclusions (the registry-level DEFAULT_EXCLUDED_TOOLS list plus the manifest's own excluded_tools — applied before anything else and, for the default list, with no per-agent override), tier filter (Core / Workflow / Specialized surface), capability gate (policy.can_invoke_tool), and an approval gate if the action is privileged — which suspends the turn to a signed checkpoint and resumes with the real result.

↓validated
Execute

Sandbox execution

Code runs in one of four drivers, network-off by default. Secrets are injected as ephemeral env vars at this moment and zeroized after — never entering the agent's context.

↓structured result · {ok, error_type, repair_hint}
Persist & recover

Record → (repair loop)

The effect and its result are written to the causal chain and content store. On failure the typed error is fed back in-session for a bounded repair attempt; the LoopGuard halts only on mechanical budgets.

Sandbox drivers — isolation is mechanical
default

bubblewrap

--unshare-all, read-only root, workspace bind-mount. Network is granted per exec, never inherited: NetworkAccess is only a ceiling ("may this agent ever reach the network"), and holding it grants nothing. share_net turns on for one exec only when an approval was validated for it.

containerized

docker

--network none hardcoded (always network-off), workspace volume, no inherited gateway env; extra mounts are read-only.

vm · stubbed

microvm

Firecracker; dependency bootstrap not yet implemented. Network isolation not guaranteed — the one driver that can't promise it.

in-process

wasm

In-process wasmtime, WASI Preview 1. No network, no host dependency. Bounded: 20 B fuel units + 512 MiB. JS agents compile here via Javy.

Storage — three classes, one discipline

Transactional · SQLite

Fast-moving state in gateway.db (+ knowledge.db): revisions & aliases, approvals & workflow events, causal-event mirror & execution traces, memories & tags, published reports (FTS5), scheduled jobs.

Content-addressed · immutable

Content store keyed by SHA-256 (content/sha256/ab/c123…); the layer store holds dependency trees as tar.zst, deduplicated by digest and mounted at build-declared paths.

Append-only · JSONL

The causal chain (history/causal_chain.jsonl), hash-chained and mirrored into the queryable causal_events table. Retention: traces 30 d, events 90 d (0 = forever), pruned on startup.

Egress — where content is allowed to flow (data-envelopes)
Lattice

The egress label

Content carries an EgressLabel — the set of sinks it may reach (local model, remote model, another agent, a federated peer, network, persistence, the user). Labels narrow monotonically as content flows (a meet-lattice); the one path that widens a label is an operator declassification grant (below), never inference. Named shorthands: unrestricted, no_remote_model, local_only. Labels are gateway-assigned metadata, never LLM-inferred.

Chokepoint

Withheld at the model boundary

A policy driver wraps every LLM call. For each message / tool result it looks up the label; if the target sink is excluded it substitutes an indication — never the bytes — and asserts the surviving content is echoed verbatim. The one place content leaves for a model.

Routing

Taint follows the request

Before a completion the batch's labels intersect; the gateway picks a provider whose class the result label allows, reroutes to an eligible preset, or refuses if none qualifies — rather than downgrade. A provider with no declared egress class is treated as remote (fail-closed), so restricted content is never sent to an unclassified endpoint. Recorded as egress.provider_selected.

At rest

Labels persist with the content

Memories, execution traces, and digests store an egress_label_json; recall, search, and the post-session digest filter by target sink, so local_only content can't re-enter a remote turn across sessions. Legacy-unlabeled rows resolve via a configured default (fail-closed option: no_remote_model). Two more object classes are labelled as durable objects in their own tables: artifacts (artifact_egress_labels, v78) and the agent workspace (agent_workspace_egress_labels, v79) — the latter closing the content-movement laundering path, where tainted bytes were written to the workspace and re-read as clean.

Widening · P-15.3

Declassification is a grant, not a judgment

A label widens only via an explicit, operator-approved declassification grant — content- or host-scoped, optionally expiring, revocable at any time, and causal-logged (egress.declassified on grant, grant_revocation on revoke). Expiry and revocation are re-checked at use time, not just at grant time. Never inferred from content, never agent-set, never granted by LLM judgment. Refusals offer the grant that would unblock them, so a boundary refusal is actionable rather than a dead end (grants.list / revoke, the room's G panel).

Credentials — the vault the agent never reads

Storage & ceremony

AES-256-GCM with a per-entry nonce; master key from env or key file. credential_setup runs a human-in-the-loop ceremony: a user_prompt step suspends to an approval and the operator enters the secret masked — the LLM proposes the flow but never sees the value.

Injection & refresh

At execution the gateway injects the secret server-side — into an HTTP header / query / body (response redacted), or as a sandbox env var via credential_env — then zeroizes it. On a 401 it attempts a single OAuth auto-refresh. Nothing crosses into agent context.

Immutability — five distinct guarantees

Immutable revisions

Each agent_revisions row is content-addressed by content_digest (status candidate → ready → rejected/archived). Running sessions stay pinned; promotion never mutates a revision.

Content-addressed by hash

Any change to a blob yields a new SHA-256 handle. Blobs are never overwritten — editing is re-storing under a new address.

Append-only causal chain

The hash-chained audit trail can be extended but not rewritten; entry_hash / prev_hash make tampering detectable.

Insert-only findings

The security_findings table is insert-only; only triage state may change after a finding is written.

Signed capsules

A cognitive capsule is revision-pinned, closure-complete, secret-free, content-addressed and Ed25519-signed — a portable identity that can't be silently altered.

runtime.lock

The pinned execution closure (locked layers + artifacts). A session binds a revision and its runtime_lock_hash, so a run is reproducible.

Error taxonomy & the repair loop

Typed failures

Every failed call returns { ok:false, error_type, message, repair_hint? }. The error_type enum:

validationpermission resourceexecution conflictquota_exceeded not_foundtimeout fatal

Per-kind retry is pre-committed: transient_env → bounded retry + backoff; capability_denied → no retry (use the lawful next moves); input_contract → repair once; output_contract_unmet → re-delegate / decompose / escalate, never blind-retry.

LoopGuard — the only thing that halts

Judgment layers observe; only the LoopGuard stops a session, on mechanical budgets:

tool_failure_budget · P-7.5 no_meaningful_progress · P-7.7 rotating_polling · P-7.19 child_failure_budget · P-7.20 repeated_irrecoverable_rejection repeated_spawn_identity

permission errors are excluded from the failure budget; fatal aborts immediately. The divergence Sentinel only escalates on a confirmed FeedbackIgnored — the same error repeated after actionable feedback — distinguishing a stuck agent from productive repair.

Not part of the tool surface

Excluded from every agent by default. DEFAULT_EXCLUDED_TOOLS hides workbench_* and artifact_project registry-wide — including from future/custom manifests and from tool_discover's catalog. These back the operator workbench console, so they carry universal inert prompt weight and zero legitimate agent callers. There is deliberately no per-agent override (tool_discover cannot re-enable an excluded tool), which is why the default list may only ever contain tools with no real users; per-agent excluded_tools composes on top of it.

agent_install was removed (P-9.2): agents are seeded only through revision-create + promote, never a one-shot install. emergency_stop is a capability and runtime trigger, not a callable LLM tool. There are no constitution_resolve_proposal, anomaly_resolve, session_fork, or admin_escalation_* native tools — those flows run through operator/CLI/RPC surfaces, not the agent's tool registry.

Never auto-evolved — the foundational exemption

The evolution loop may not touch its own load-bearing agents. Exempt: planner, coder, sealed_evaluator, static_evaluator, unit_test_runner, auditor, specialized_builder, agent-factory, evolution-orchestrator, memory-curator, evolution-steward, agent-adapter.
